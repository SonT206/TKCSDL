\section{Conceptual Database Design}\label{s:conceptual}

This section presents the conceptual database model for the SmartDroneDelivery platform. The conceptual model identifies the main entities, their attributes, the relationships between entities, and the cardinalities of those relationships. The conceptual model serves as the basis for the logical relational schema developed in Section~\ref{s:logical}.

\subsection{Entity Identification}\label{s:entities}

Based on the requirements and business rules documented in Chapter~\ref{c:analysis}, the following twenty-three entities are identified. They are organized into seven functional groups to ensure comprehensive coverage without operational redundancy.

\paragraph{1. User and Authorization Group.}
\begin{itemize}
    \item \textbf{system\_user} — Stores authentication credentials and account statuses for all actors. Avoids reserved SQL keywords.
    \item \textbf{role} — Defines standard operational roles (\texttt{CUSTOMER}, \texttt{DISPATCHER}, \texttt{STATION\_OPERATOR}, \texttt{LOGISTICS\_MANAGER}, \texttt{SYSTEM\_ADMIN}).
    \item \textbf{permission} — Defines granular permissions (e.g., \texttt{CREATE\_ORDER}, \texttt{ASSIGN\_DRONE}, \texttt{CONFIRM\_PICKUP}).
    \item \textbf{user\_role} — Bridge table implementing the many-to-many relationship between users and roles.
    \item \textbf{role\_permission} — Bridge table implementing the many-to-many relationship between roles and permissions.
\end{itemize}

\paragraph{2. Customer and Address Group.}
\begin{itemize}
    \item \textbf{customer} — Stores customer profile information, optionally linked to a system user account.
    \item \textbf{customer\_address} — Stores one or more delivery addresses per customer, including precise geographic coordinates for drone navigation.
\end{itemize}

\paragraph{3. Delivery Order and Package Group.}
\begin{itemize}
    \item \textbf{delivery\_order} — Represents customer delivery requests, tracking customer requested time, estimated arrival, and lifecycle state.
    \item \textbf{package} — Stores physical package specifications (weight and dimensions in centimeters) associated with an order.
    \item \textbf{order\_status\_history} — Append-only record capturing every status transition of a delivery order.
\end{itemize}

\paragraph{4. Landing Station and Drone Management Group.}
\begin{itemize}
    \item \textbf{landing\_station} — Stores physical takeoff/landing stations, coordinates, and drone capacity.
    \item \textbf{station\_status\_history} — Records the history of station status transitions (maintenance, availability).
    \item \textbf{station\_operator\_assignment} — Records staffing assignments of station operators to landing stations over defined time periods.
    \item \textbf{drone} — Stores drone serial numbers, models, operational statuses, battery levels, and payload capacities.
\end{itemize}

\paragraph{5. Delivery Execution and Telemetry Group.}
\begin{itemize}
    \item \textbf{delivery\_activity} — Central operational entity representing each discrete execution attempt for an order, linking the drone, departure station, and destination station.
    \item \textbf{package\_station\_event} — Records package physical handling events at landing stations (arrival, pickup confirmation, loading, unloading).
    \item \textbf{tracking\_record} — Stores high-frequency GPS and telemetry data captured during drone flight.
    \item \textbf{delivery\_exception} — Records flight failures, anomalies, or disruptions during a delivery activity.
\end{itemize}

\paragraph{6. Delivery Confirmation Group.}
\begin{itemize}
    \item \textbf{delivery\_confirmation} — Records formal handover proof upon successful delivery, linked 1:0..1 with the order and referencing digital proof in object storage.
\end{itemize}

\paragraph{7. Audit, Route, and AI Assistance Group.}
\begin{itemize}
    \item \textbf{audit\_log} — Immutable system audit trail capturing user actions, before/after JSON snapshots, and IP addresses.
    \item \textbf{delivery\_route} — Stores planned flight path metadata for a delivery activity.
    \item \textbf{route\_point} — Stores ordered waypoints along a planned delivery route.
    \item \textbf{ai\_recommendation} — Stores persistent outputs of AI recommendation models (drone recommendations and ETA predictions).
\end{itemize}

\subsection{Entity Attributes}\label{s:attributes}

This section specifies the attributes and data types of each identified entity.

\paragraph{system\_user.}
Stores user account credentials and authentication state.
\begin{itemize}
    \item \texttt{user\_id} — Primary key (\texttt{BIGINT GENERATED ALWAYS AS IDENTITY}).
    \item \texttt{username} — Unique username (\texttt{VARCHAR(100)}).
    \item \texttt{password\_hash} — Cryptographic password hash (\texttt{VARCHAR(255)}).
    \item \texttt{email} — Unique email address (\texttt{VARCHAR(255)}).
    \item \texttt{phone\_number} — Unique phone number (\texttt{VARCHAR(20)}).
    \item \texttt{is\_active} — Account active flag (\texttt{BOOLEAN}).
    \item \texttt{created\_at}, \texttt{updated\_at} — Account audit timestamps (\texttt{TIMESTAMPTZ}).
\end{itemize}

\paragraph{role.}
Defines system roles.
\begin{itemize}
    \item \texttt{role\_id} — Primary key (\texttt{BIGINT}).
    \item \texttt{role\_name} — Unique role identifier (\texttt{VARCHAR(50)}).
    \item \texttt{description} — Description of role responsibilities (\texttt{VARCHAR(255)}).
\end{itemize}

\paragraph{permission.}
Defines functional permissions.
\begin{itemize}
    \item \texttt{permission\_id} — Primary key (\texttt{BIGINT}).
    \item \texttt{permission\_name} — Unique permission code (\texttt{VARCHAR(100)}).
    \item \texttt{description} — Permission explanation (\texttt{VARCHAR(255)}).
\end{itemize}

\paragraph{user\_role.}
Associates users with roles.
\begin{itemize}
    \item \texttt{user\_id}, \texttt{role\_id} — Composite primary key and foreign keys.
    \item \texttt{assigned\_at} — Timestamp of role assignment (\texttt{TIMESTAMPTZ}).
\end{itemize}

\paragraph{role\_permission.}
Associates roles with permissions.
\begin{itemize}
    \item \texttt{role\_id}, \texttt{permission\_id} — Composite primary key and foreign keys.
\end{itemize}

\paragraph{customer.}
Stores customer profiles.
\begin{itemize}
    \item \texttt{customer\_id} — Primary key (\texttt{BIGINT}).
    \item \texttt{user\_id} — Foreign key to \texttt{system\_user} (\texttt{BIGINT UNIQUE NULL}).
    \item \texttt{customer\_name} — Full name (\texttt{VARCHAR(100)}).
    \item \texttt{phone\_number} — Primary contact number (\texttt{VARCHAR(20) UNIQUE}).
    \item \texttt{email} — Contact email (\texttt{VARCHAR(255) UNIQUE}).
    \item \texttt{created\_at} — Registration timestamp (\texttt{TIMESTAMPTZ}).
\end{itemize}

\paragraph{customer\_address.}
Stores customer delivery locations.
\begin{itemize}
    \item \texttt{address\_id} — Primary key (\texttt{BIGINT}).
    \item \texttt{customer\_id} — Foreign key to \texttt{customer} (\texttt{BIGINT NOT NULL}).
    \item \texttt{address\_label} — Label such as ``Home'' or ``Office'' (\texttt{VARCHAR(50)}).
    \item \texttt{address\_line} — Street address (\texttt{VARCHAR(255) NOT NULL}).
    \item \texttt{ward}, \texttt{district}, \texttt{city} — Administrative divisions (\texttt{VARCHAR(100)}).
    \item \texttt{latitude}, \texttt{longitude} — Coordinates (\texttt{NUMERIC(9,6)}).
    \item \texttt{is\_default} — Default address flag (\texttt{BOOLEAN NOT NULL DEFAULT FALSE}).
    \item \texttt{created\_at} — Creation timestamp (\texttt{TIMESTAMPTZ}).
\end{itemize}

\paragraph{delivery\_order.}
Represents delivery requests.
\begin{itemize}
    \item \texttt{order\_id} — Primary key (\texttt{BIGINT}).
    \item \texttt{customer\_id} — Foreign key to \texttt{customer} (\texttt{BIGINT NOT NULL}).
    \item \texttt{delivery\_address\_id} — Foreign key to \texttt{customer\_address} (\texttt{BIGINT NOT NULL}).
    \item \texttt{order\_status} — Current lifecycle state (\texttt{VARCHAR(30) NOT NULL}).
    \item \texttt{requested\_delivery\_time} — Customer desired delivery time (\texttt{TIMESTAMPTZ}).
    \item \texttt{estimated\_arrival\_at} — System estimated arrival time (\texttt{TIMESTAMPTZ}).
    \item \texttt{created\_at} — Order placement timestamp (\texttt{TIMESTAMPTZ NOT NULL}).
    \item \texttt{completed\_at}, \texttt{cancelled\_at} — Finalization timestamps (\texttt{TIMESTAMPTZ}).
    \item \texttt{cancellation\_reason} — Explanation if cancelled (\texttt{VARCHAR(255)}).
\end{itemize}

\paragraph{package.}
Stores package specifications.
\begin{itemize}
    \item \texttt{package\_id} — Primary key (\texttt{BIGINT}).
    \item \texttt{order\_id} — Foreign key to \texttt{delivery\_order} (\texttt{BIGINT NOT NULL}).
    \item \texttt{description} — Content description (\texttt{VARCHAR(500)}).
    \item \texttt{weight\_kg} — Weight in kilograms (\texttt{NUMERIC(10,2) > 0}).
    \item \texttt{length\_cm}, \texttt{width\_cm}, \texttt{height\_cm} — Dimensions in centimeters (\texttt{NUMERIC(10,2) > 0}).
    \item \texttt{package\_status} — Status code (\texttt{VARCHAR(30) NOT NULL}).
    \item \texttt{created\_at} — Creation timestamp (\texttt{TIMESTAMPTZ}).
\end{itemize}

\paragraph{order\_status\_history.}
Maintains immutable order lifecycle audit.
\begin{itemize}
    \item \texttt{status\_history\_id} — Primary key (\texttt{BIGINT}).
    \item \texttt{order\_id} — Foreign key to \texttt{delivery\_order} (\texttt{BIGINT NOT NULL}).
    \item \texttt{status} — Recorded status value (\texttt{VARCHAR(30) NOT NULL}).
    \item \texttt{changed\_by} — Foreign key to \texttt{system\_user} (\texttt{BIGINT}).
    \item \texttt{reason} — Transition reason (\texttt{VARCHAR(255)}).
    \item \texttt{changed\_at} — Transition timestamp (\texttt{TIMESTAMPTZ NOT NULL}).
\end{itemize}

\paragraph{landing\_station.}
Stores physical landing stations.
\begin{itemize}
    \item \texttt{station\_id} — Primary key (\texttt{BIGINT}).
    \item \texttt{station\_code} — Unique station code (\texttt{VARCHAR(50) UNIQUE NOT NULL}).
    \item \texttt{station\_name} — Human-readable name (\texttt{VARCHAR(100) NOT NULL}).
    \item \texttt{address} — Physical address (\texttt{VARCHAR(255)}).
    \item \texttt{latitude}, \texttt{longitude} — Coordinates (\texttt{NUMERIC(9,6)}).
    \item \texttt{capacity} — Maximum drone capacity (\texttt{INTEGER >= 0}).
    \item \texttt{status} — Operational state (\texttt{VARCHAR(30) NOT NULL}).
    \item \texttt{created\_at} — Creation timestamp (\texttt{TIMESTAMPTZ}).
\end{itemize}

\paragraph{station\_status\_history.}
Maintains station operational history.
\begin{itemize}
    \item \texttt{history\_id} — Primary key (\texttt{BIGINT}).
    \item \texttt{station\_id} — Foreign key to \texttt{landing\_station} (\texttt{BIGINT NOT NULL}).
    \item \texttt{status} — Recorded station state (\texttt{VARCHAR(30) NOT NULL}).
    \item \texttt{changed\_by} — Foreign key to \texttt{system\_user} (\texttt{BIGINT}).
    \item \texttt{reason} — Transition reason (\texttt{VARCHAR(255)}).
    \item \texttt{changed\_at} — Transition timestamp (\texttt{TIMESTAMPTZ NOT NULL}).
\end{itemize}

\paragraph{station\_operator\_assignment.}
Records operator staffing at stations.
\begin{itemize}
    \item \texttt{assignment\_id} — Primary key (\texttt{BIGINT}).
    \item \texttt{station\_id} — Foreign key to \texttt{landing\_station} (\texttt{BIGINT NOT NULL}).
    \item \texttt{user\_id} — Foreign key to \texttt{system\_user} representing the operator (\texttt{BIGINT NOT NULL}).
    \item \texttt{assigned\_from}, \texttt{assigned\_to} — Assignment validity window (\texttt{TIMESTAMPTZ}).
    \item \texttt{is\_active} — Flag indicating active assignment (\texttt{BOOLEAN NOT NULL DEFAULT TRUE}).
    \item \texttt{created\_at} — Assignment timestamp (\texttt{TIMESTAMPTZ}).
\end{itemize}

\paragraph{drone.}
Stores drone specifications and status.
\begin{itemize}
    \item \texttt{drone\_id} — Primary key (\texttt{BIGINT}).
    \item \texttt{serial\_number} — Physical identifier (\texttt{VARCHAR(100) UNIQUE NOT NULL}).
    \item \texttt{model} — Model designation (\texttt{VARCHAR(100)}).
    \item \texttt{status} — Operational status (\texttt{VARCHAR(30) NOT NULL}).
    \item \texttt{max\_payload\_kg} — Maximum payload capacity (\texttt{NUMERIC(10,2) > 0}).
    \item \texttt{battery\_level} — Current battery level (\texttt{NUMERIC(5,2)} between 0 and 100).
    \item \texttt{station\_id} — Foreign key to current \texttt{landing\_station} (\texttt{BIGINT NULL}).
    \item \texttt{created\_at} — Registration timestamp (\texttt{TIMESTAMPTZ}).
\end{itemize}
Note: Drones do not store an \texttt{order\_id}; drone assignment is mediated via \texttt{delivery\_activity}.

\paragraph{delivery\_activity.}
The operational mediator representing delivery execution attempts.
\begin{itemize}
    \item \texttt{activity\_id} — Primary key (\texttt{BIGINT}).
    \item \texttt{order\_id} — Foreign key to \texttt{delivery\_order} (\texttt{BIGINT NOT NULL}).
    \item \texttt{drone\_id} — Foreign key to \texttt{drone} (\texttt{BIGINT NOT NULL}).
    \item \texttt{pickup\_station\_id} — Foreign key to origin \texttt{landing\_station} (\texttt{BIGINT}).
    \item \texttt{destination\_station\_id} — Foreign key to destination \texttt{landing\_station} (\texttt{BIGINT}).
    \item \texttt{assigned\_by} — Foreign key to dispatching \texttt{system\_user} (\texttt{BIGINT}).
    \item \texttt{scheduled\_at} — Planned execution time (\texttt{TIMESTAMPTZ}).
    \item \texttt{activity\_status} — Execution state (\texttt{VARCHAR(30) NOT NULL}).
    \item \texttt{started\_at}, \texttt{ended\_at} — Execution timestamps (\texttt{TIMESTAMPTZ}).
    \item \texttt{previous\_activity\_id} — Self-referencing foreign key linking preceding failed attempt (\texttt{BIGINT NULL}).
    \item \texttt{created\_at} — Creation timestamp (\texttt{TIMESTAMPTZ}).
\end{itemize}

\paragraph{package\_station\_event.}
Records package handling at stations.
\begin{itemize}
    \item \texttt{event\_id} — Primary key (\texttt{BIGINT}).
    \item \texttt{package\_id} — Foreign key to \texttt{package} (\texttt{BIGINT NOT NULL}).
    \item \texttt{station\_id} — Foreign key to \texttt{landing\_station} (\texttt{BIGINT NOT NULL}).
    \item \texttt{event\_type} — Handling event type (\texttt{VARCHAR(30) NOT NULL}).
    \item \texttt{performed\_by} — Foreign key to station operator \texttt{system\_user} (\texttt{BIGINT}).
    \item \texttt{occurred\_at} — Event timestamp (\texttt{TIMESTAMPTZ NOT NULL}).
    \item \texttt{note} — Operational remarks (\texttt{VARCHAR(255)}).
\end{itemize}

\paragraph{tracking\_record.}
Stores high-frequency in-flight telemetry.
\begin{itemize}
    \item \texttt{tracking\_id} — Primary key (\texttt{BIGINT}).
    \item \texttt{activity\_id} — Foreign key to \texttt{delivery\_activity} (\texttt{BIGINT NOT NULL}).
    \item \texttt{latitude}, \texttt{longitude} — Coordinates (\texttt{NUMERIC(9,6)}).
    \item \texttt{altitude\_m} — Altitude in meters (\texttt{NUMERIC(10,2) >= 0}).
    \item \texttt{speed\_kmh} — Ground speed in km/h (\texttt{NUMERIC(10,2) >= 0}).
    \item \texttt{battery\_level} — Battery percentage (\texttt{NUMERIC(5,2)}).
    \item \texttt{recorded\_at} — Telemetry capture timestamp (\texttt{TIMESTAMPTZ NOT NULL}).
\end{itemize}

\paragraph{delivery\_confirmation.}
Formal delivery proof.
\begin{itemize}
    \item \texttt{confirmation\_id} — Primary key (\texttt{BIGINT}).
    \item \texttt{order\_id} — Foreign key to \texttt{delivery\_order} (\texttt{BIGINT UNIQUE NOT NULL}).
    \item \texttt{activity\_id} — Foreign key to successful \texttt{delivery\_activity} (\texttt{BIGINT UNIQUE NOT NULL}).
    \item \texttt{confirmed\_by} — Foreign key to verifying \texttt{system\_user} (\texttt{BIGINT}).
    \item \texttt{receiver\_name} — Name of package recipient (\texttt{VARCHAR(100) NOT NULL}).
    \item \texttt{receiver\_phone} — Recipient contact phone (\texttt{VARCHAR(20)}).
    \item \texttt{confirmation\_method} — Method code (\texttt{VARCHAR(30) NOT NULL}).
    \item \texttt{evidence\_object\_key} — Object storage key for digital signature/photo proof (\texttt{VARCHAR(255)}).
    \item \texttt{confirmed\_at} — Handover timestamp (\texttt{TIMESTAMPTZ NOT NULL}).
    \item \texttt{note} — Delivery remarks (\texttt{VARCHAR(500)}).
\end{itemize}

\paragraph{delivery\_exception.}
Records flight failures and incidents.
\begin{itemize}
    \item \texttt{exception\_id} — Primary key (\texttt{BIGINT}).
    \item \texttt{activity\_id} — Foreign key to \texttt{delivery\_activity} (\texttt{BIGINT NOT NULL}).
    \item \texttt{exception\_type} — Incident category (\texttt{VARCHAR(50) NOT NULL}).
    \item \texttt{description} — Detailed incident narrative (\texttt{TEXT}).
    \item \texttt{detected\_at} — Incident detection timestamp (\texttt{TIMESTAMPTZ NOT NULL}).
    \item \texttt{resolved\_at} — Resolution timestamp (\texttt{TIMESTAMPTZ}).
    \item \texttt{resolved\_by} — Foreign key to resolving \texttt{system\_user} (\texttt{BIGINT}).
    \item \texttt{resolution} — Corrective action explanation (\texttt{TEXT}).
\end{itemize}

\paragraph{audit\_log.}
System-wide security and modification audit log.
\begin{itemize}
    \item \texttt{log\_id} — Primary key (\texttt{BIGINT}).
    \item \texttt{user\_id} — Foreign key to actor \texttt{system\_user} (\texttt{BIGINT NULL}).
    \item \texttt{entity\_name} — Target table name (\texttt{VARCHAR(100) NOT NULL}).
    \item \texttt{record\_id} — Target record primary key (\texttt{BIGINT}).
    \item \texttt{action\_type} — Operation type (\texttt{VARCHAR(50) NOT NULL}).
    \item \texttt{old\_value}, \texttt{new\_value} — Before/after JSON snapshots (\texttt{JSONB}).
    \item \texttt{action\_time} — Audit timestamp (\texttt{TIMESTAMPTZ NOT NULL}).
    \item \texttt{ip\_address} — Client network address (\texttt{INET}).
\end{itemize}

\paragraph{delivery\_route and route\_point.}
Planned flight trajectories and waypoints.
\begin{itemize}
    \item \texttt{delivery\_route}: \texttt{route\_id} (PK), \texttt{activity\_id} (FK UNIQUE), \texttt{total\_distance\_km}, \texttt{estimated\_duration\_min}, \texttt{created\_at}.
    \item \texttt{route\_point}: \texttt{route\_point\_id} (PK), \texttt{route\_id} (FK), \texttt{sequence\_number}, \texttt{latitude}, \texttt{longitude}, \texttt{altitude\_m}.
\end{itemize}

\paragraph{ai\_recommendation.}
Persistent outputs from AI analytics services.
\begin{itemize}
    \item \texttt{recommendation\_id} — Primary key (\texttt{BIGINT}).
    \item \texttt{order\_id} — Foreign key to \texttt{delivery\_order} (\texttt{BIGINT NOT NULL}).
    \item \texttt{activity\_id} — Foreign key to \texttt{delivery\_activity} (\texttt{BIGINT NULL}).
    \item \texttt{recommendation\_type} — Recommendation category (\texttt{VARCHAR(50) NOT NULL}).
    \item \texttt{recommended\_drone\_id} — Foreign key to suggested \texttt{drone} (\texttt{BIGINT NULL}).
    \item \texttt{estimated\_duration\_min} — Model estimated flight minutes (\texttt{NUMERIC(10,2)}).
    \item \texttt{confidence\_score} — Confidence level (\texttt{NUMERIC(5,4)} between 0 and 1).
    \item \texttt{model\_version} — Version identifier of the AI service (\texttt{VARCHAR(50)}).
    \item \texttt{created\_at} — Recommendation generation timestamp (\texttt{TIMESTAMPTZ}).
\end{itemize}

\subsection{Relationships and Cardinalities}\label{s:relationships}

The relationships and cardinalities between the twenty-three entities are defined as follows, strictly conforming to the business rules:

\begin{itemize}
    \item \textbf{customer} 1 : N \textbf{customer\_address} — One customer owns many addresses; each address belongs to exactly one customer (BR-01).
    \item \textbf{customer} 1 : N \textbf{delivery\_order} — One customer creates many delivery orders; each order belongs to one customer (BR-02).
    \item \textbf{customer\_address} 1 : N \textbf{delivery\_order} — One address can be the destination for many orders; each order specifies one destination address (BR-03, BR-04).
    \item \textbf{delivery\_order} 1 : N \textbf{package} — One order contains one or more packages; each package belongs to one order (BR-06, BR-07).
    \item \textbf{delivery\_order} 1 : N \textbf{order\_status\_history} — One order accumulates multiple historical status records (BR-10, BR-11).
    \item \textbf{delivery\_order} 1 : N \textbf{delivery\_activity} — One order can have multiple execution attempts (initial and rescheduled) (BR-19, BR-20).
    \item \textbf{delivery\_order} 1 : 0..1 \textbf{delivery\_confirmation} — One order has at most one successful delivery confirmation (BR-33).
    \item \textbf{delivery\_activity} 1 : 0..1 \textbf{delivery\_confirmation} — A confirmation is tied to exactly one successful delivery activity attempt (BR-35).
    \item \textbf{delivery\_activity} 0..1 : 1 \textbf{delivery\_activity} — Rescheduled activities link to their preceding attempt via \texttt{previous\_activity\_id} (BR-22).
    \item \textbf{drone} 1 : N \textbf{delivery\_activity} — A drone serves many delivery activities over time, but only one active flight at any instant (BR-15, BR-16).
    \item \textbf{landing\_station} 1 : N \textbf{drone} — A station accommodates multiple parked drones (BR-25).
    \item \textbf{landing\_station} 1 : N \textbf{station\_status\_history} — A station preserves its operational status changes (BR-26).
    \item \textbf{landing\_station} 1 : N \textbf{station\_operator\_assignment} — A station has multiple operator staffing assignments over time (BR-27).
    \item \textbf{system\_user} 1 : N \textbf{station\_operator\_assignment} — A station operator user can be assigned to multiple stations over time (BR-27).
    \item \textbf{package} 1 : N \textbf{package\_station\_event} — A package undergoes multiple station handling events (arrival, pickup, loading) (BR-29, BR-30).
    \item \textbf{landing\_station} 1 : N \textbf{package\_station\_event} — A station processes events for many packages (BR-31).
    \item \textbf{delivery\_activity} 1 : N \textbf{tracking\_record} — Each activity generates an immutable series of flight telemetry points (BR-12).
    \item \textbf{delivery\_activity} 1 : N \textbf{delivery\_exception} — An activity may encounter zero, one, or multiple exception incidents (BR-13, BR-21).
    \item \textbf{delivery\_activity} 1 : 0..1 \textbf{delivery\_route} — An activity has at most one planned route.
    \item \textbf{delivery\_route} 1 : N \textbf{route\_point} — A route is composed of an ordered sequence of waypoints.
    \item \textbf{delivery\_order} 1 : N \textbf{ai\_recommendation} — An order may receive recommendations from multiple AI models over time.
    \item \textbf{system\_user} N : N \textbf{role} — Mediated by \textbf{user\_role}.
    \item \textbf{role} N : N \textbf{permission} — Mediated by \textbf{role\_permission}.
    \item \textbf{system\_user} 1 : N \textbf{audit\_log} — Users generate audit log entries across the system (BR-37, BR-38).
\end{itemize}

\section{Logical Database Design}\label{s:logical}

This section derives the logical relational schema from the conceptual model. The relational schema is presented in standard notation, with primary keys denoted by (PK), foreign keys by (FK), and unique constraints by UNIQUE.

\subsection{Relational Schema}

\begin{verbatim}
SYSTEM_USER(user_id PK, username UNIQUE, password_hash,
  email UNIQUE, phone_number UNIQUE, is_active,
  created_at, updated_at)

ROLE(role_id PK, role_name UNIQUE, description)

PERMISSION(permission_id PK, permission_name UNIQUE,
  description)

USER_ROLE(user_id PK/FK, role_id PK/FK, assigned_at)

ROLE_PERMISSION(role_id PK/FK, permission_id PK/FK)

CUSTOMER(customer_id PK, user_id FK UNIQUE,
  customer_name, phone_number UNIQUE, email UNIQUE,
  created_at)

CUSTOMER_ADDRESS(address_id PK, customer_id FK,
  address_label, address_line, ward, district, city,
  latitude, longitude, is_default, created_at)

DELIVERY_ORDER(order_id PK, customer_id FK,
  delivery_address_id FK, order_status,
  requested_delivery_time, estimated_arrival_at,
  created_at, completed_at, cancelled_at,
  cancellation_reason)

PACKAGE(package_id PK, order_id FK, description,
  weight_kg, length_cm, width_cm, height_cm,
  package_status, created_at)

ORDER_STATUS_HISTORY(status_history_id PK, order_id FK,
  status, changed_by FK, reason, changed_at)

LANDING_STATION(station_id PK, station_code UNIQUE,
  station_name, address, latitude, longitude,
  capacity, status, created_at)

STATION_STATUS_HISTORY(history_id PK, station_id FK,
  status, changed_by FK, reason, changed_at)

STATION_OPERATOR_ASSIGNMENT(assignment_id PK,
  station_id FK, user_id FK, assigned_from,
  assigned_to, is_active, created_at)

DRONE(drone_id PK, serial_number UNIQUE, model, status,
  max_payload_kg, battery_level, station_id FK,
  created_at)

DELIVERY_ACTIVITY(activity_id PK, order_id FK,
  drone_id FK, pickup_station_id FK,
  destination_station_id FK, assigned_by FK,
  scheduled_at, activity_status, started_at, ended_at,
  previous_activity_id FK, created_at)

PACKAGE_STATION_EVENT(event_id PK, package_id FK,
  station_id FK, event_type, performed_by FK,
  occurred_at, note)

TRACKING_RECORD(tracking_id PK, activity_id FK,
  latitude, longitude, altitude_m, speed_kmh,
  battery_level, recorded_at)

DELIVERY_CONFIRMATION(confirmation_id PK,
  order_id FK UNIQUE, activity_id FK UNIQUE,
  confirmed_by FK, receiver_name, receiver_phone,
  confirmation_method, evidence_object_key,
  confirmed_at, note)

DELIVERY_EXCEPTION(exception_id PK, activity_id FK,
  exception_type, description, detected_at,
  resolved_at, resolved_by FK, resolution)

AUDIT_LOG(log_id PK, user_id FK, entity_name,
  record_id, action_type, old_value, new_value,
  action_time, ip_address)

DELIVERY_ROUTE(route_id PK, activity_id FK UNIQUE,
  total_distance_km, estimated_duration_min,
  created_at)

ROUTE_POINT(route_point_id PK, route_id FK,
  sequence_number, latitude, longitude, altitude_m)

AI_RECOMMENDATION(recommendation_id PK, order_id FK,
  activity_id FK, recommendation_type,
  recommended_drone_id FK, estimated_duration_min,
  confidence_score, model_version, created_at)
\end{verbatim}

\subsection{Primary Keys, Foreign Keys, and Candidate Keys}

Every base table possesses a single-column surrogate primary key (\texttt{BIGINT GENERATED ALWAYS AS IDENTITY}). Bridge tables (\texttt{user\_role}, \texttt{role\_permission}) employ composite primary keys. Candidate natural keys are protected with \texttt{UNIQUE} constraints:
\begin{itemize}
    \item \texttt{system\_user.username}, \texttt{system\_user.email}, \texttt{system\_user.phone\_number}
    \item \texttt{customer.phone\_number}, \texttt{customer.email}
    \item \texttt{drone.serial\_number}
    \item \texttt{landing\_station.station\_code}
    \item \texttt{delivery\_confirmation.order\_id} and \texttt{delivery\_confirmation.activity\_id}
    \item \texttt{delivery\_route.activity\_id}
    \item \texttt{route\_point(route\_id, sequence\_number)}
\end{itemize}

\subsection{Functional Dependencies and Normalization}

All twenty-three relations satisfy Third Normal Form (3NF):

\paragraph{First Normal Form (1NF).}
All column values are atomic. Address components are separated into discrete attributes; dimensions are stored as individual numeric values (\texttt{length\_cm}, \texttt{width\_cm}, \texttt{height\_cm}); and multiple addresses or packages are represented as separate relational rows rather than composite strings.

\paragraph{Second Normal Form (2NF).}
Every non-key attribute is fully functionally dependent on the entire primary key. In composite-key tables (\texttt{user\_role}, \texttt{role\_permission}), non-key attributes depend on both component keys.

\paragraph{Third Normal Form (3NF).}
No transitive dependencies exist between non-key attributes. For example, \texttt{delivery\_order} references \texttt{customer\_id} and does not store customer contact details; \texttt{delivery\_confirmation} does not store customer or drone data; and \texttt{tracking\_record} references \texttt{activity\_id} without redundantly storing drone attributes.

\subsection{Integrity Constraints}

The relational schema enforces six categories of integrity constraints:

\begin{enumerate}
    \item \textbf{Entity Integrity}: Guaranteed by surrogate primary keys that are automatically generated, non-null, and unique across all tables.
    \item \textbf{Referential Integrity}: Enforced via foreign key constraints. Operational master data (\texttt{customer}, \texttt{drone}, \texttt{landing\_station}) use \texttt{ON DELETE RESTRICT} to prevent accidental deletion of operational history. Security bridge tables use \texttt{ON DELETE CASCADE}. User audit references use \texttt{ON DELETE SET NULL} to preserve audit trails if user accounts are archived.
    \item \textbf{Domain Integrity}: Column data types and explicit \texttt{CHECK} constraints ensure valid domain values (coordinates within $[-90, 90]$ and $[-180, 180]$, positive dimensions and payload capacities, battery percentages between $0$ and $100$).
    \item \textbf{Uniqueness Constraints}: Natural identifiers and 1:0..1 cardinalities are strictly enforced by database-level \texttt{UNIQUE} indexes.
    \item \textbf{Business Integrity}: Total package weight must not exceed assigned drone capacity (BR-18); address must belong to the ordering customer (BR-04).
    \item \textbf{Temporal Integrity}: In \texttt{delivery\_activity}, \texttt{started\_at < ended\_at}; in \texttt{station\_operator\_assignment}, \texttt{assigned\_from < assigned\_to}.
\end{enumerate}

\subsection{State Transition Lifecycle Models}\label{s:lifecycle}

The system defines formal lifecycles for its three central stateful entities:

\paragraph{Delivery Order Lifecycle.}
\begin{verbatim}
PENDING
   |
   +---> APPROVED ---> ASSIGNED ---> IN_TRANSIT
   |                                     |
   |                                     +---> DELIVERED (Terminal)
   |                                     |
   |                                     +---> FAILED
   |                                              |
   |                                              +---> ASSIGNED (Rescheduled)
   |                                              |
   |                                              +---> CANCELLED (Terminal)
   |
   +---> REJECTED (Terminal)
   |
   +---> CANCELLED (Terminal)
\end{verbatim}

\paragraph{Package Lifecycle.}
\begin{verbatim}
CREATED -> AT_STATION -> PICKED_UP -> IN_TRANSIT -> DELIVERED
                                         |
                                         +-> FAILED -> RETURNED / DAMAGED
\end{verbatim}

\paragraph{Delivery Activity Lifecycle.}
\begin{verbatim}
ASSIGNED -> PREPARING -> IN_TRANSIT -> DELIVERED / FAILED / CANCELLED
\end{verbatim}

\subsection{Representative Business Queries}

The following queries confirm that the physical design directly answers operational needs:

\paragraph{Retrieve orders for a customer with latest status.}
\begin{verbatim}
SELECT order_id, order_status, requested_delivery_time,
       estimated_arrival_at, created_at
FROM   delivery_order
WHERE  customer_id = :customer_id
ORDER  BY created_at DESC;
\end{verbatim}

\paragraph{Retrieve package pickup confirmation history at stations.}
\begin{verbatim}
SELECT pse.event_id, pse.package_id, ls.station_name,
       pse.event_type, su.username AS operator_name, pse.occurred_at
FROM   package_station_event pse
JOIN   landing_station ls ON ls.station_id = pse.station_id
LEFT   JOIN system_user su ON su.user_id = pse.performed_by
WHERE  pse.package_id = :package_id
ORDER  BY pse.occurred_at ASC;
\end{verbatim}

\paragraph{Trace rescheduling chain for a delivery order.}
\begin{verbatim}
SELECT activity_id, drone_id, activity_status,
       previous_activity_id, started_at, ended_at
FROM   delivery_activity
WHERE  order_id = :order_id
ORDER  BY created_at ASC;
\end{verbatim}

\paragraph{Retrieve flight telemetry for monitoring.}
\begin{verbatim}
SELECT recorded_at, latitude, longitude, altitude_m, speed_kmh, battery_level
FROM   tracking_record
WHERE  activity_id = :activity_id
ORDER  BY recorded_at DESC
LIMIT  50;
\end{verbatim}

\section{Chapter Summary}\label{s:ch3summary}

\qquad This chapter detailed the conceptual, logical, and physical database design for the SmartDroneDelivery platform. The model comprises twenty-three normalized relations organized into seven functional groups.

Key architectural enhancements include introducing \texttt{delivery\_activity} to decouple orders from drones, adding \texttt{station\_operator\_assignment} and \texttt{package\_station\_event} to formalize station staffing and package pickup workflows, incorporating \texttt{previous\_activity\_id} to track rescheduling chains, and referencing external digital proof keys in \texttt{delivery\_confirmation}.

The logical schema satisfies 3NF and enforces six categories of integrity constraints. Finally, complete PostgreSQL DDL statements and an index strategy were presented, providing a rigorous, efficient, and fully traceable implementation ready for comprehensive validation in Chapter~\ref{c:test}.
