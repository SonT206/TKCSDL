
\section{Testing Objectives}
The goal of testing is to ensure that the database schema meets business requirements, 
maintains data integrity, and supports operational workflows such as order tracking, 
drone assignment, and audit logging.

\section{Testing Approach}
We applied both functional and non-functional testing:
\begin{itemize}
    \item \textbf{Functional Testing}: Verify that each entity and relationship behaves correctly.
    \item \textbf{Integrity Testing}: Ensure foreign keys and constraints prevent invalid data.
    \item \textbf{Performance Testing}: Measure query execution time for critical operations.
    \item \textbf{Security Testing}: Check user roles and audit logs for accountability.
\end{itemize}

\section{Test Cases}
\subsection{Customer and Order}
\begin{itemize}
    \item Insert a new Customer and verify that DeliveryOrder references the correct CustomerID.
    \item Attempt to insert an Order with a non-existent CustomerID (should fail).
\end{itemize}

\subsection{Drone and Tracking}
\begin{itemize}
    \item Assign a Drone to an Order and confirm that Tracking records are linked to both.
    \item Simulate a drone failure by changing Drone.Status to "Maintenance" and reassign the order.
\end{itemize}

\subsection{Workflow and AuditLog}
\begin{itemize}
    \item Update DeliveryWorkflow status from "In Transit" to "Delivered" and check that AuditLog records the action.
    \item Verify that only authorized Users can update Workflow entries.
\end{itemize}

\subsection{Lost Package Scenario}
\begin{itemize}
    \item Remove a package from Tracking updates and confirm that AuditLog records the investigation.
    \item Ensure DeliveryOrderStation helps locate the last station where the package was registered.
\end{itemize}

\section{Evaluation Criteria}
\begin{itemize}
    \item \textbf{Consistency}: All foreign keys enforce referential integrity.
    \item \textbf{Reliability}: The schema supports error handling (e.g., drone replacement).
    \item \textbf{Performance}: Queries on Tracking and Workflow execute within acceptable time.
    \item \textbf{Scalability}: The schema can handle multiple drones, stations, and customers simultaneously.
    \item \textbf{Security}: AuditLog ensures accountability for all user actions.
\end{itemize}

\section{Results}
Testing confirmed that:
\begin{itemize}
    \item The schema prevents invalid references and maintains consistency.
    \item Drone reassignment and lost package scenarios are traceable through Tracking and AuditLog.
    \item Performance remains stable under simulated high load.
    \item User actions are properly logged, supporting transparency and auditing.
\end{itemize}
